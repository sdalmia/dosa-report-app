Where these figures come from

Posist reads data/store_health/posist_daily.csv. One row per store per date. The store column is the Posist deployment label. Money is rupees, including values written with thousands separators. A blank cell stays blank.

{{ posist_columns|join(", ") }}

Menu mix reads data/store_health/menu_mix.csv from Posist Insights Menu Analysis. Columns are store, item, total sales, total orders, contribution percent, period start, and period end. The box lists the top items for the dates present in that file. When the file covers more than 30 days, only the latest 30 days present are listed. A store with no matching rows says menu mix is not on file for this store.

The calendar reads data/store_health/sales_pred_vs_actual.csv and shows the next 30 days from today in Asia/Kolkata. A network file uses the same columns without store. A store calendar adds store. Low, mid, and high on this drop are that store's share of the network judgment band, not a separate model. Actual Gross is that same day's Posist gross, including a real zero. It is never replaced by net. If the calendar file has a real Actual Net for a day, it is shown on its own line labelled Actual Net. Low, mid, and high come from the network band, which is a net figure, so Actual Gross is not like-for-like with them. A day with no Posist row stays blank. A later day does not reuse an earlier day's gross. Predictions and variance stay blank unless the calendar file has them. A blank is not zero. Status may be share_of_network_band or not_on_deployment_report, as well as pending, actual, or actual_provisional_eod.

{{ calendar_columns|join(", ") }}

Active employees read data/store_health/keka_active.csv. Keka has no Active flag. The count is the Org Locations employee count minus people on the Relieved Employees report, as of 3 Oct 2026. People still in notice stay in the count. A blank is unmatched, not zero. The old keka.csv headcount is not used. Primary lead still comes from keka.csv and is the largest reporting line, not a confirmed single store manager. posist_store joins a Posist label only when it matches one store.

{{ keka_active_columns|join(", ") }}

Mystery audit reads data/store_health/mystery_audit.csv. Scores stay as written. A store with no row stays empty. The Brand row is the brand aggregate, not that store's score.

{{ audit_columns|join(", ") }}

Reelo reads data/store_health/reelo.csv. The window on this drop is Last 30 Days, 03 Sep 2026 to 03 Oct 2026. Phone capture is valid visits / (valid + blocked) x 100. A shorter posist_store label joins only when it matches one store. Match status not in Reelo is shown as those words. inferred is not a confirmed address match.

{{ reelo_columns|join(", ") }}

Famepilot reads data/store_health/famepilot.csv. Public rating and public review count are one pair. Private rating, private review count, and overall reviews are shown when the cell has a value. A tie in main threat is shown in full. The capture used the Past 30 days preset; the dates printed on screen were 26 Sep 26 - 02 Oct 26 (7 days), which is not a verified 30-day range. A blank location is no Famepilot location, and the rating stays blank.

{{ famepilot_columns|join(", ") }}
